# BinTools 设计文档 · 热图 MVP

**日期**：2026-05-16
**版本**：v1（MVP 范围）

---

## 1. 项目概述

### 1.1 一句话定位

面向不会编程的实验室科研人员的桌面端生物分析可视化软件。第一版只做一件事：**上传 Excel 表格 → 调参数 → 导出发表级别的基因表达热图**。

### 1.2 目标用户

研究生 / 博士 / 博士后阶段的湿实验研究人员。常见状态：
- 用 Excel 整理数据；
- 不会 R / Python；
- 写论文时需要高质量配图；
- 数据未发表，不愿上传到云服务。

### 1.3 非目标用户（明确排除）

- 临床医生与公卫研究者（生存分析等不在 MVP 内）；
- 本科教学场景；
- 通用工具型用户（不追求覆盖所有表格画图需求）。

### 1.4 MVP 范围

**只做热图。** 做到发表质量，做到对小白零门槛，然后再扩展到火山图 / PCA / GO·KEGG 富集图。

不做：
- 项目保存（每次启动都是新会话）；
- 云同步 / 用户账号；
- 暗色模式（首版发布后再加）；
- 英文 UI（首版仅简体中文，多语言放到后续路线）。

支持的导出格式（明确范围）：PNG、JPG、SVG、PDF。

## 2. 整体架构

Electron 桌面应用，内部分两层：

```
┌─────────────────────────────────────────────────┐
│  Electron 主进程（Main Process）                │
│  • 启动窗口、原生菜单                            │
│  • 文件对话框（"选 Excel" / "保存图片"）         │
│  • 应用生命周期                                  │
└─────────────────────────────────────────────────┘
              │ IPC（仅文件对话框相关）
              ▼
┌─────────────────────────────────────────────────┐
│  Electron 渲染进程（Renderer Process）          │
│  浏览器环境，跑 React 应用                       │
│                                                  │
│  • UI 层：React + Tailwind CSS                   │
│  • 图表层：Plotly.js                             │
│  • 计算层（纯 JS）：                             │
│      - SheetJS（xlsx 解析）                      │
│      - ml-hclust（层次聚类）                     │
│      - 自写归一化函数                            │
└─────────────────────────────────────────────────┘
```

**架构边界**：

- 99% 功能在渲染进程，主进程只管系统能力。
- 没有数据库、没有服务器、没有云。所有数据全部留在用户内存中，会话结束即销毁。
- 全离线运行。

**为什么这么定**：

- AI 在浏览器 JS 上调试最顺，对一个不会编程的开发者而言风险最低；
- 减少进程间通信复杂度；
- 数据隐私模型最强（科研人员核心诉求）。

## 3. 核心模块拆分

渲染层拆成 7 个独立模块，每个只做一件事：

| 模块 | 职责 | 输入 | 输出 |
|---|---|---|---|
| **FileLoader** | 选/解析 Excel | 文件路径 | sheet 列表 + 原始单元格 |
| **DataValidator** | 检查合法性、识别基因名列 | 原始单元格 | 结构化数据 + 问题列表 |
| **DataPreview** | 显示前 10 行让用户确认 | 结构化数据 | 用户确认 / 修正 |
| **Normalizer** | z-score / log2 / 均值居中 | 数值矩阵 | 归一化后矩阵 |
| **ClusteringEngine** | 行/列层次聚类 | 矩阵 + 距离度量 | 排序索引 + 树状图坐标 |
| **HeatmapRenderer** | 调 Plotly.js 画图 | 矩阵 + 参数 | 渲染到 DOM |
| **Exporter** | 导出图片 | Plotly 图实例 + 格式 | 保存到文件 |

### 3.1 设计原则

1. **数据单向流动** —— 用户操作只改"参数 state"，整条链路（归一化 → 聚类 → 渲染）自动重跑。
2. **模块边界明确** —— 输入输出契约清晰，内部实现可以独立替换。例如 ml-hclust 换成更快的聚类库时，只改 `ClusteringEngine` 内部。
3. **小白友好为硬约束** —— 任何模块的对外参数都要有人话名字 + 悬停解释。

### 3.2 数据流示例

用户切换"归一化方式"为 z-score：

```
用户点击 z-score
  → 参数 state 更新
  → Normalizer 收到新设置，重新归一化
  → ClusteringEngine 因输入变化，重新聚类
  → HeatmapRenderer 收到新数据，重画
```

无显式刷新逻辑，React state 驱动。

## 4. 用户操作流程

```
①打开 app
   │
   ▼
②欢迎页 → 点 "上传 Excel"（或点内置示例数据集）
   │
   ▼
③系统文件选择器 → 选 .xlsx
   │
   ▼
④自动解析第一个 sheet → 显示数据预览（前 10 行）
   │
   ├── 数据正确 → 点"确认"
   │
   └── 列识别错了 → 手动指定基因名列 → 确认
   │
   ▼
⑤主界面：左侧参数面板 + 右侧热图预览
   │ 任何参数改变 → 图立刻刷新（200ms 防抖）
   │
   ▼
⑥点右上角 "导出" → 选格式（PNG / JPG / SVG / PDF） → 保存位置 → 完成
```

### 4.1 关键决定

- **欢迎页内置示例数据集**：用户不用准备 Excel 也能立即看到效果。
- **数据预览不能跳过**：让用户确认"软件理解的数据"和他的预期一致。
- **实时预览不带"应用"按钮**：参数改完立刻生效；防抖 200ms 防卡顿。
- **导出按钮固定在右上角**：全程可见。

## 5. UI 视觉风格 + 主界面布局

### 5.1 视觉风格

仿 Claude.com 的克制美学，明确反"AI 工具感"。

| 元素 | 选择 | 理由 |
|---|---|---|
| 背景色 | 奶油 / 米白（`#FAF9F5`） | 暖色基调 |
| 主文字 | 深炭灰（`#2D2A26`） | 阅读柔和 |
| 强调色 | 赤陶色（`#CC785C`） | 仅用于主按钮和图表强调 |
| 标题字体 | Source Serif / Tiempos | 编辑型质感 |
| 正文字体 | Inter | 干净清晰 |
| 卡片 / 边框 | 几乎无 | 用留白和细分割线建立层次 |
| 阴影 | 极淡或无 | 拒绝悬浮卡片 + 渐变 + 霓虹三件套 |
| 图标 | lucide-icons（线条款） | 不用 emoji 不用填充图标 |

### 5.2 主界面布局

```
╔═══════════════════════════════════════════════════════════════════╗
║   BinTools                                          [ 导出 ▾ ]    ║
║   ─────────────────────────────────────────────────────────────   ║
║   ┌─ 数据 ──────────────┐    ┌──────────────────────────────────┐ ║
║   │  expr_matrix.xlsx    │    │                                  │ ║
║   │  200 基因 × 12 样本   │    │                                  │ ║
║   │  [ 重新上传 ]         │    │                                  │ ║
║   ├─ 归一化 ─────────────┤    │         热图实时预览              │ ║
║   │  ○ 原始              │    │       （Plotly.js 渲染）          │ ║

║   │  ☑ 列聚类             │    │                                  │ ║
║   │  距离: 欧氏距离 ▾     │    │                                  │ ║
║   ├─ 外观 ───────────────┤    │                                  │ ║

   ↑ 左侧 ~320px 宽           ↑ 右侧自适应，热图最大化利用空间
```

### 5.3 关键决定

- **左侧面板分组用细分割线**而非卡片包装：视觉连贯不闹腾。
- **顶部只有 logo + 导出按钮**：其他控件全部下沉到侧边面板。
- **数据卡片始终显示文件名和尺寸**：让用户知道在处理什么。
- **窗口可拉伸**：热图自适应宽度。

## 6. Excel 输入格式

### 6.1 标准格式

```
        样本1  样本2  样本3  样本4  样本5  ...
GAPDH   1245   1356   1188   1422   1198
ACTB    8932   9201   8845   9388   9012
TP53    234    198    301    287    245
...
```

- 第 1 行 = 表头（样本名）；
- 第 1 列 = 基因名（字符串）；
- 其余 = 数值。

### 6.2 容错策略

| 情况 | 处理方式 |
|---|---|
| 第一列不是字符串而是数值 | 报警告，让用户手动指定"基因名列" |
| 多个 sheet | 弹下拉让用户选 |
| 单元格为空 / "NA" / "NaN" / "-" | 当缺失值处理；默认跳过该行，用户可选"补 0"或"补行均值" |
| 重复基因名 | 报警告，自动加后缀 `_1` `_2` 区分 |
| 数据规模过大（行数 >5000 或列数 >50） | 阻塞性确认框："数据较大，渲染可能需要 10-30 秒。继续？" |
| 全部为 0 的行 | 自动跳过（聚类无意义） |

### 7.1 小白友好硬约束

1. **每个参数旁有 `?` 图标**，悬停弹一句话解释。
   例：「Z-score：让每个基因的数值落在 -2~+2，方便看相对变化。」
2. **默认值即论文级配置**：Z-score + 行/列聚类开 + 欧氏距离 + 红蓝配色。用户什么都不调，导出来的图就是发表质量。
3. **"高级"开关默认关闭**：Ward.D / 曼哈顿距离等不常用选项藏起来。

## 8. 错误处理

| 场景 | 用户看到什么 |
|---|---|
| 文件不是 .xlsx / .xls | "只支持 Excel 文件（.xlsx 或 .xls），请重新选择。" |
| 文件损坏打不开 | "文件无法打开，可能已损坏。" |
| Excel 完全没有数值列 | 进入"数据预览"页，标红："没找到数值数据，请检查表格。" |
| 第一列识别为基因名失败 | 进入"列映射"页：「第几列是基因名？」 |
| 缺失值很多（>30%） | 黄色横幅："你的数据有 35% 的缺失值，热图可能不准确。" |
| 数据规模过大（行数 >5000 或列数 >50） | 阻塞性确认框（与第 6 节同条件、同处理） |
| 聚类失败（如全 0 行未清理） | 自动退化为"不聚类模式"，顶部提示："聚类失败，已自动关闭。" |
| 导出失败（如磁盘写入权限） | "保存失败：[具体原因]，请换个位置。" |
| 渲染崩了（极端） | 不闪退；显示 fallback："渲染出错，请简化数据或重试。" |

**核心原则**：永远不让 app 静默失败或崩溃。每个错误都给"人话解释 + 下一步该做什么"。

## 9. 测试策略

| 层 | 怎么测 | 工具 |
|---|---|---|
| **纯函数** | 单元测试归一化、聚类的输入输出 | Vitest |
| **核心组件** | 上传 → 预览 → 渲染整链路 | React Testing Library |
| **测试数据集** | 5 套 Excel 覆盖典型与边界情况 | 放在 `tests/fixtures/` |
| **跨平台手动测试** | 完整流程在 Mac + Windows 各跑一遍 | 真机 |
| **回归清单** | 每次发版前手动跑一遍 | `tests/manual-checklist.md` |

### 9.1 测试数据集

1. `small_clean.xlsx` —— 20 基因 × 6 样本，干净数据；
2. `medium_normal.xlsx` —— 200 基因 × 24 样本，典型 RNA-seq 规模；
3. `large_stress.xlsx` —— 5000 基因 × 50 样本，性能压测；
4. `with_missing.xlsx` —— 含 ~10% 缺失值（NA、空、"-"）；
5. `weird_format.xlsx` —— 第一列非基因名、有空白行、有重复名。
